# Script Desk: notes for Claude

Web app that reviews scripts for a weekly **Spanish Christian Bible-teaching YouTube podcast** (host Juan Sánchez, non-technical, mostly on a phone; Adrian produces). It adjusts delivery for YouTube. It never rewrites doctrine or Bible verses. Spanish and English UI.
**Scope (2026-10-22):** Juan writes at essay/PhD level; the job is taking a sound message from ~90 to 95–100 for YouTube (hook, retention, spoken voice, return viewers, packaging, ads). Line-level nits for untrained speakers are secondary and live behind «Más detalles». Guided flow: 3 steps, Escribir · Mejorar · Publicar.

## Layout
- `index.html`, `sw.js`, icons, manifest: the **built** site served by GitHub Pages (https://jadri47.github.io/script-desk/). Never hand-edit `index.html`.
- `src/`: all source. `src/build/` has the UI files (`*_ui.js`, `*.css`, `base.html`, `*_logic.js`), the build scripts (`build.py`, `build_examples.py`, `build_standalone.py`, `patch_*.py`) and Playwright checks (`pw*.py`). `src/eval/` has the node tests.
- `supabase/functions/sd-ai/index.ts`: the only Anthropic call site (server-side, key stays in Supabase secrets). Project `vuvwoxjlmoegstpalngx`; tables `sd_ai_usage`, `sd_docs`, `sd_team`; RPCs `sd_is_member`, `sd_month_cost`. Deploy with the Supabase tool, not from here.

## Build (from `src/build`, in this order)
```
python3 build.py && python3 build_examples.py && python3 build_standalone.py
```
Output: `src/standalone/site/index.html` (the site) and `src/build/work.html` (the Claude-artifact version). Derived files (`work.html`, `full.js`, `logic.js`, `all.js`, `standalone/site/`) are gitignored: **never edit them**. New UI files must be added to the concatenation list in `patch_ui.py`.

## Tests (from `src/`)
```
node eval/run.js; node eval/timing_test.js; node eval/polish_test.js; node eval/score_test.js; node eval/cats_test.js; node eval/rail_test.js; node eval/rules_test.js; node eval/coach_test.js; node eval/report_test.js
```
Playwright checks: `cd src/build; python3 pwXX.py`. They open `src/standalone/site/index.html` relative to the script (the `SDU` line at the top of each file), so they work wherever the repo is cloned. Main ones: `pwreport` (step 2 editor's report: one AI call per script version, vetted items, readiness numbers, «Más detalles» closed), `pwai` (AI status bubble on the score: thinking + clock, «Listo» closes after 5 s and leaves a check, failure + Reintentar, cancelled = nothing, counted once), `pwalts` (alternatives: radio list per change, word choices on ad warnings, old saved report still loads), `pwsteps` (3-step bar, step 3 approve / recorded stay on 3), `pwdc` (tap/bar selects a paragraph; on a phone the bar does not open the keyboard, green accepted cards collapse/expand + revert, grey ignored cards + restore, stale-apply guard), `pwwk` (paragraph review), `pwcl` (color families, legend filter, minimap markers), `pwrl` (rail + minimap in the script box), `pwsc` (score pill; flaky on "off persists after reload" and "show button appears": rerun, two clean passes = OK), `pwcoach` (guided step 2 coach: one decision at a time, batch, questions, keys, phone), `pwcoachai` (automatic AI: call counts, verse guard, $5 budget), `pwverdict`, `pwfx` (paragraph review: every points badge equals the real score change, a +0 says why, refs/reading are notes), `pwerr`, `pwpack`, `pwpp` (prompter: countdown reset on close, Enter on a button is that button), `pwdark` (dark theme: suggestion and section cards readable, chips under the OS scheme), `pwep` (logged episodes: `hookPassed` written as a boolean, old row-object records still read), `pwstale` (typed text is never replaced by an older answer or snapshot: Ask «todo el guion», Deshacer, «Usar esta versión», «Volver al original» refuse when the script changed since), `pwex`, `pwmt`, `pwtm`, `pwat`, `pwhw` (header never wraps 900–1920 px; ~8 min), `pwtoast`, `pw10`. `pw9` follows the cards by phase (27 checks, needs `mock_sb.js`). They use `mock_sb.js` instead of Supabase. Screenshots go to the OS temp folder (`script-desk-pw/`).

### Running on Windows (Adrian's PC)
- Python 3 + `pip install playwright` + `python -m playwright install chromium`; Node 18+.
- Set `PYTHONUTF8=1` (PowerShell: `$env:PYTHONUTF8=1`) before building: the build scripts open UTF-8 files without an explicit encoding.
- Use `python` instead of `python3` if that is what the PC has.
- `src/package.json` (`type: commonjs`) must stay: a stray `Claude_Programming/package.json` with `type: module` otherwise breaks the node tests and `build_examples.py`. Keep a test file out of `build/` if it is named like a Python stdlib module (`pwd.py` once broke every `pw*.py`; now `pwdl.py`).
- `SD_BROWSER=firefox|webkit python pwXX.py` runs the six main checks (`pwdc pwwk pwcl pwrl pwsc pwtoast`) in another engine (`python -m playwright install firefox webkit`). `pwsc` is chromium-only (CDP). Known engine results: `docs/DECISIONS.md`.

## Design rules that matter
- **The user-visible number is readiness** (`readinessOf`, `score_logic.js`): rules 40 (ads 20, packaging 12, length/close 8; runtime < 8 min costs 4) + editor 60 (6 report areas, rating 1–5 → 0/4/7/9/10). No report ⇒ only «Anuncios y empaque r/40», never an invented editor part; red ⇒ ≤ 69. The pill, verdict, popover and «a → b» (`projectedReadiness`) all use it; the editor part changes only on «Volver a evaluar». Pinned in `eval/report_test.js`.
- Editor's report (step 2; `report_logic.js` pure + `report_ui.js`): one `complex` AI call per script version (not `auto`, so the $5 auto pause doesn't block it), verses masked as ⟦Vn⟧, script last. `vetReport` keeps an item only if its original is found exactly once, doesn't touch a verse, adds no reference/quote and no new ad/packaging risk. Red ad risks from the rules come first, then the items, one at a time. Saved with the episode as optional `report`.
- Alternatives (2026-10-25): the same report call returns up to 2 `alts` per item and up to 3 `words` per flagged term; each is vetted like a replacement (`vetReport` / `vetWords`: a word alternative must leave fewer sensitive terms and never touch a verse). Step 2 shows a radio list per change and one choice per word (all its occurrences, `reportWordRows`); a yellow ad warning joins step 2 only when the report has words for it. `alts`/`words` are optional in a saved report (`rpClean`). A term inside a Scripture sentence (`scriptureSentences`: a verse span or a «dice la Biblia» marker) keeps its word; the card says so (2026-10-28, pick B).
- Long answers (2026-10-29, A + B): the report call carries only the editor's judgement; the fragments «Proponer con IA» and the coach would ask go in their own calls after it (`fixesPrompt`: no script, `REPORT_FIX_BATCH` = 6 per call, `complex` tier, not `auto`; `rpFixPump` appends each batch to `report.fixes` and saves it; a failed batch has its own Reintentar; `coachAiPump` waits while `RP.fix.run`). A cut answer (server code `truncated` + `raw`) is repaired by `repairJson` (keeps complete elements only, never a half string); the report is kept with `partial: true` and says «La respuesta se cortó». `report.before` = the readiness shown when the report landed; `report.costUsd` only when the bill carried it. Pinned by `pwfixes`, `pwai` (modes `trunc`/`truncjunk`), `eval/report_test.js` ("repair:"). Server `MAX_TOKENS.complex` = 16,000.
- Walk (2026-10-26): the number is in the score pill only; its popover is the report (`rpPopHTML`), «a → b posible» comes from `rpProjected`. The editor part counts applied changes (`effectiveReport`, `itemGain`, `readinessOf(..., text)`, `report.baseline`): an estimate «según el editor» until «Medir de nuevo». Step 2 = one change card at a time (`report_ui.js`), step 3 = six cards then Grabar (`pub_ui.js`), tips in `tips_ui.js` (`sd-tips-off=1` off; `mock_sb.js` sets it). Pinned by `pwbub`, `pwwalk`, `pwpub`, `pwchrome`, `eval/report_test.js`. The print-only smoke suites pw pw2 pw4 pw7 pw8 pwat pw10 pwh pwd2 pwdl pwa pwm pwb pwl (no `ok()` checks: they print what the screens say) run again on today's screens since 2026-10-29 (`sd-intro`, `sd-more-open`, the ⋯ menu for «Modo completo», `goPhase`, `#epList`); a red there is a crash, not a failed check.
- Bug review (2026-10-29): the open list is `docs/BUGS-2026-10.md` (grep it before touching a feature it names). Rules it pinned: a
  report change keeps the reference set (`refsKey`); the «Proponer con IA» button masks and vets like a batch; typed text is never
  replaced by an older answer or snapshot (`pwstale`); starting an example makes no AI call (`pwbub`); a same-language adaptation
  keeps every quote verbatim (`trVerse`).
- AI status (`aistatus_ui.js`): every AI call goes through one wrapper on `caps.sample` (a getter/setter, so later assignments and test mocks are wrapped too). A new AI feature needs nothing to show the bubble; pass `aiLabel`/`aiRetry` only for a name or a retry button (they never reach the connection). While the report runs the verdict says «Esperando el informe del editor», never «Listo para grabar».
- Old score v2 (`scoreOf`, internal now: «Más detalles» chips and coach ordering): 100 − weights of open checks − small penalty for dismissed ones; any red ⇒ ≤ 69. Counted checks (long, fillers, weak, regional, aitell, onscreen, jargon, pulpit, openers, cta) give partial credit: 1 point per instance over the limit, capped by `SCORE_CAP`. Weights live in one table (`SCORE_W`); ladders are pinned in `eval/score_test.js`.
- Desktop (≥900 px wide and ≥560 px tall) is a split view: script left, review right. Phone: single column, stepBar fixed at the bottom; in step 2 the script docks at the top.
- Coach (inside step 2's «Más detalles» since 2026-10-22, `sd-more-open=1` opens it; `coach_logic.js` pure + `coach_ui.js` + `coach_ai.js`): `buildDecisions` orders red risk > one safe batch > questions (keyword, central idea, next episode, title, with choices from the script) > choices by real gain > notes; `projectedScore` is the "Nota a → b" figure. Automatic AI: one call per up to 8 decisions, verses sent as tokens (dropped if altered), every option re-verified, stops at $5/month (`COACH_AI_MONTH_USD`), daily/rate limits, or 3 calls per review when cost is unknown. «Ver por párrafos» (`sd-coach-off`) shows the walker below; walker-only suites set it.
- Paragraph review (`walk_ui.js`): highlights use the CSS Custom Highlight API over the editor text (the editor DOM is not changed); positions come from `buildFixCards(..., cap = Infinity)`.
- Choosing the paragraph: a real tap/click/arrow key inside a paragraph (`pointerup`/`keyup`, not `selectionchange`, so re-rendering after Apply never moves the review) or the vertical bar per paragraph in the rail (`.rl-bar`, `railSelect`) calls `wkGo(i, false)`. The phone editor only goes full screen from the maximizer button, never on tap.
- Decision log `state.fixLog` (fix_ui.js): every Apply adds a `done` entry (uid, paragraph, time, why, option, word delta, score before→after, before/after text with context, previous field/cold-open values); every "Ahora no" adds `skip` entries. The walker shows them under the open cards: green collapsed cards that expand to the details + "Revertir este cambio" (`fxRevert`: finds the changed text by its context and puts the old text back; refuses if that text was edited since), grey struck cards with "Restaurar". Reset on Revisar/demo/series/language change.
- `applyProposal` guards: refuses on stale text (script changed since the review; trailing whitespace ignored), says so when a patch changes nothing, flashes + scrolls to the changed text, and for cold-open / title / keyword / thumbnail / description fixes says where the change went (that was the "accept does nothing" bug).
- Keep the script text **last** in every AI prompt. The server puts the house rules and Bible-version rule in one cached system block; it is below the 512-token cache minimum, so caching is currently a no-op (see `sd_ai_usage` cache columns).
- Ad warnings are our reading of YouTube's rules, never a promise. Timing limits we invented are labelled as ours.

## Color code (text + timeline)
- `cats_logic.js` is the single table: families hi (can remove ads), mid (can limit ads), cut (would be removed), fill (fillers), pol (to polish), with priority hi > mid > cut > fill > pol. Colors live as `--c-*` / `--m-*` tokens in `theme2026.css` (light + dark). Color is never the only cue: each family also has its own line style, and timeline markers have their own shape.
- Legend chips (`catLegendHTML`) double as filters (state in localStorage `sd-cats-off`, `html.cat-off-<id>` classes). The 3-lane `timelineHTML` (`base.html`) and `manuscriptHTML` are expert-mode only now.
- Guided step 2: `rail_ui.js` lays a rail (minute per paragraph, timeline shapes, editor notes) over the script box's left padding and a minimap above the text (window follows scroll; tap or drag to jump; tap a marker to open its paragraph). It is an overlay positioned from paragraph rects, the editor DOM is untouched; typing removes it until the next review. Pure data in `rail_logic.js` (`railItems`, `railCrowd`). Editor notes default on for desktop, off on phone (`sd-rail-cues`); verses toggle `sd-rail-refs`.
